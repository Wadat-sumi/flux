# Flux full-stack Azure deployment

Run `bash scripts/deploy-azure.sh` for the guided single-command Central India deployment. Use the current [macOS + GHCR deployment runbook](deploy-mac-ghcr.md) for prerequisites, automatic state bootstrap, remaining Portal secret entry and recovery. This supersedes the unprovisioned Azure Container Registry/Docker build path. No Azure registry resource remains in Terraform.

Status: not deployed. Azure login, cost/plan review, state storage, provisioning, live secret/network checks and HTTPS verification remain for the owner's joint review. Local Terraform format/schema validation and mock staged plans are separate from a successful cloud deployment.

A single Azure Container App serves React and the Node API. Private PostgreSQL 16, managed identities, Key Vault, VNet/private DNS, logs and a separate administrative migration job are defined. GHCR stores the immutable OCI image. A manually dispatched GitHub Actions workflow runs the required tests, uses Buildah to build and Podman to smoke-test, and optionally publishes to GHCR. Your Mac needs Azure CLI/Terraform/Git, with no local container tool. The Linux image build and GitHub publication have not yet been executed.

Private GHCR pulls use a read-only package token stored only in Azure Key Vault. Container Apps/jobs use managed identities to resolve the vault reference; the token is not a Terraform input or data lookup. Public pulls are explicitly optional. Workflow publication uses GitHub's automatically minted job token, with no stored publishing key. Runtime and migration database credentials remain separate. Database provisioning still places sensitive database values in protected state. An Azure Blob backend with Entra authentication/locking is now declared and needs non-secret storage settings at init. Never commit state/plans/tfvars or print secret values.

The stages are automatic state-storage bootstrap → foundation → Portal secret entry → verified GHCR image → private database → migration-job creation/execution → application → HTTPS/live checks. Review each saved plan before apply. No resources should modify an existing resource group, and no apply/login or cloud build/publication has been performed by the assistant. Azure resources and GitHub Actions/package usage can incur costs; choose region/quotas/tier during the joint review. B1ms is a development default, not a measured cloud 120-user sizing recommendation. Keep one API replica/CPU worker until distributed coordination exists.

Rotate pull/provider tokens by entering a new vault version and verifying the consuming service's refresh/pull behavior. Database rotation requires a coordinated password/connection-reference/role migration. Test backups/restores and roll back to a previously verified immutable image without destructive schema changes. Do not run a destroy against existing infrastructure. The complete commands and stop conditions are in the linked runbook.
